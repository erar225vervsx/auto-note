# 長い資料を生成AIで要約するとき 抜けと誤りを防ぐ5手順

「長い報告書を生成AIに要約してもらったら、会議で『それ、資料のどこに書いてあった?』と聞かれて答えられなかった」。そんな冷や汗をかいたことはないでしょうか。

要約は、生成AIの使い方のなかでも特に身近なものです。帝国データバンクの2026年の調査でも、企業の生成AIの主な用途として「文章の作成・要約・校正」が挙がっていました。一方で、同じ調査では活用上の課題として「情報の正確性」を挙げる企業が約半数にのぼっています。

要約がやっかいなのは、**間違いがあっても、元の資料を読まないかぎり気づけない**ことです。元を読まずに済ませたいから要約を頼んでいるのに、その要約が正しいかは元を読まないと分からない。この矛盾をどう扱うかが、この記事のテーマです。

ここでは、報告書・調査資料・長いメールのやりとりなど、数十ページ単位の資料を生成AIで要約するときの手順を、指示文の例と確認のコツつきで紹介します。議事録づくりとは違い、「すでにある文書を短くする」場面に絞っています。

## 生成AIの要約で起きやすい4つのこと

まず、どんな失敗が起きやすいのかを知っておくと、確認する場所が絞れます。

### 1. 大事な点が抜ける

要約は「短くする」作業なので、何かが落ちるのは当然です。問題は、**落としてはいけないものが落ちる**ことです。たとえば「ただし〇〇の場合は除く」という例外、「現時点では未確定」という但し書き、末尾の付録にだけ書かれたリスクなどです。

長い文書については、気になる研究もあります。2023年に発表された論文「Lost in the Middle」では、言語モデルに長い文章を与えたとき、必要な情報が文章の先頭や末尾にある場合に比べて、**中ほどにある場合は性能が大きく下がる**傾向が報告されました。当時のモデルを対象にした実験なので、いまのツールにそのまま当てはまるとは限りませんが、「長い資料の真ん中は抜けやすいかもしれない」と意識しておくのは損になりません。

### 2. 意味が少しずれる

「検討する」が「実施する」に、「一部の部署で」が「全社で」に、「増加傾向」が「大幅に増加」に。言い換えの途中で、意味が少しだけ強くなったり、範囲が広がったりすることがあります。一文ずつ読むと自然なので、見落としやすいずれです。

### 3. 元の資料にないことが混ざる

生成AIは、文章をなめらかにつなぐために、一般論や「よくある結論」を補ってしまうことがあります。資料には書かれていない改善策や背景説明が、もっともらしく入り込むケースです。

### 4. 要約を重ねるほど崩れる

ソフトバンクのブログでは、約6,000字の会話をGeminiに「要約して」と繰り返し要約させる検証が紹介されています。回数を重ねるうちに固有名詞が「A・B・C」のような記号に置き換わり、経緯や細かなニュアンスが消えていったと報告されています。

職場では「部下がAIで要約したものを、上司がさらにAIで要約して報告する」という流れが起きがちです。**要約の要約は、元の情報から二段階離れている**と考えておきましょう。

## 要約を頼む前の準備:2つだけ決める

いきなり「要約して」と頼む前に、次の2つを決めておくと、要約の質も確認のしやすさも大きく変わります。

### 何のための要約か

同じ報告書でも、目的によって残すべき情報は違います。

- **判断のため**:結論、根拠、選択肢、リスク、期限
- **共有のため**:何が起きたか、誰に関係するか、次に何があるか
- **自分の理解のため**:全体の構成、用語の意味、主張の流れ

目的があいまいなまま頼むと、AIは「全体をまんべんなく薄く」まとめます。それがいちばん、使いにくい要約になりがちです。

### 入力してよい資料か

社外秘の資料や、個人情報が含まれる資料を、職場で認められていないツールに入れるのは避けましょう。迷ったら、職場の利用ルールに従うか、該当部分を伏せてから使います。この確認は、要約の精度より先に来る話です。

## 抜けと誤りを防ぐ5つの手順

ここからが本題です。手順は次の5つです。

1. 長い資料は章ごとに分けて渡す
2. 「出典の場所」をつけて要約させる
3. 「書かれていないこと」を書かせない指示を入れる
4. 要約を元の資料と突き合わせる(全部ではなく、決まった場所だけ)
5. 共有するときは「AI要約」と元資料を添える

### 手順1:長い資料は章ごとに分けて渡す

数十ページの資料を一度に渡すと、どこが抜けたのか後から追いにくくなります。目次や見出しがある資料なら、**章ごとに要約させてから、最後に全体をまとめさせる**ほうが安全です。

やり方の例です。

- 1回目:「この資料の目次(見出し一覧)を書き出してください」
- 2回目以降:章ごとに貼りつけて要約させる
- 最後:章ごとの要約を並べ、自分で全体の結論を確認する

最初に目次を出させておくと、あとで「この章の要約がない」と抜けに気づけます。手間は少し増えますが、確認の手間はむしろ減ります。

### 手順2:「出典の場所」をつけて要約させる

要約の各項目に、元の資料のどこに書かれていたか(章の名前、見出し、ページ番号など)を添えてもらいます。これだけで、確認するときに元の資料のどこを見ればよいかがすぐ分かります。

場所を示せない項目は、AIが補った可能性がある項目として、特に注意して確認します。

### 手順3:「書かれていないこと」を書かせない指示を入れる

指示文には、次のような制約を入れておきます。

- 資料に書かれていないことは書かない
- 資料から判断できない点は「資料に記載なし」と書く
- 数字・日付・固有名詞は言い換えずにそのまま書く
- 「ただし」「除く」「未定」などの条件や但し書きは省略しない

これらで誤りがなくなるわけではありませんが、AIが一般論で空白を埋めるのを減らし、確認すべき場所をはっきりさせる効果があります。

#### 指示文の例(判断のための要約)

```
あなたは資料の要約を手伝うアシスタントです。
以下の資料を、上司が「進めるか・止めるか」を判断するために要約してください。

【出力の形】
1. 結論(資料が示している結論を1〜2文)
2. 根拠(3〜5項目)
3. リスク・懸念点
4. 決まっていないこと・未確定の点
5. 期限や次の予定

【守ってほしいこと】
・各項目の末尾に、資料のどこに書かれていたか(章・見出し・ページ)を( )で書く
・資料に書かれていないことは書かない。判断できない点は「資料に記載なし」と書く
・数字、日付、固有名詞は言い換えずにそのまま書く
・「ただし」「除く」「未定」「検討中」などの条件は省略しない
・自分の意見や一般的な改善策は加えない

【資料】
(ここに本文を貼る)
```

共有のための要約なら、出力の形を「何が起きたか/誰に関係するか/次に何があるか」に変えるだけで使い回せます。

### 手順4:要約を元の資料と突き合わせる

全文を読み直していては、要約を頼んだ意味がありません。そこで、**確認する場所を決めておきます**。おすすめは次の5か所です。

1. **数字・日付・金額**:元の資料と一字一句同じか。単位(%と件、千円と円)も見る
2. **結論の強さ**:「検討する」「予定」「可能性がある」が、要約で「決定」「実施する」になっていないか
3. **範囲と主語**:「一部の」「〇〇部門では」が抜けて、話が広がっていないか
4. **条件・例外・但し書き**:元の資料にある「ただし」が要約に残っているか
5. **場所が示せない項目**:手順2で出典が空欄、またはあいまいな項目は、元の資料を検索して本当に書かれているか確かめる

もう一つ、抜けを見つけるために使えるのが、**AIにツッコミ役をさせる**方法です。

```
先ほどの要約と元の資料を比べて、次の点を指摘してください。
・元の資料にあるのに要約から抜けている重要な点
・要約で意味が強くなったり、範囲が広がったりしている箇所
・元の資料に書かれていない内容
指摘ごとに、元の資料の該当箇所を示してください。
問題が見つからない場合は「見つからない」と書いてください。
```

ただし、ツッコミ役のAIも間違えることがあります。指摘された箇所は、必ず元の資料で自分の目で確かめましょう。「AIが問題なしと言ったから問題なし」とは考えないことが大切です。

### 手順5:共有するときは「AI要約」と元資料を添える

要約をチームや上司に共有するときは、次の3点を添えます。

- 生成AIで要約したものであること
- 元の資料へのリンクや保存場所
- 自分が確認した範囲(例:「数字と結論は原文と照合済み。付録は未確認」)

こうしておけば、受け取った人が判断の前に原文に当たれます。また、受け取った側が要約をさらにAIで要約する「要約の要約」も起きにくくなります。

## 具体例:30ページの調査報告書を上司向けに要約する

ある会社員が、外部の調査会社から届いた30ページの報告書を、上司向けに要約する場面を考えてみます。

1. 報告書の目次をAIに書き出させる(全6章と付録)
2. 第1章〜第6章を1章ずつ貼りつけ、手順3の指示文で要約させる
3. 章ごとの要約を並べ、結論が「試験導入を推奨」であることを確認
4. 確認の5か所を見ていくと、ある章の要約で「対象地域では増加」が「全国的に増加」になっていたので修正
5. 付録の「調査の限界」に書かれた但し書きが要約から抜けていたので、自分で1行追加
6. 「AIで要約。数字と結論は原文と照合済み。付録は但し書きのみ確認」と添え、原文の保存場所と一緒に上司に送る

ここで大事なのは、**AIが出したものを「完成品」ではなく「確認の出発点」として扱っている**点です。原文を全部読むよりは短い時間で済み、それでいて判断に関わる部分は自分で確かめています。

## 要約だけで済ませてよい資料、原文を読むべき資料

最後に、判断の目安です。迷ったら、「要約が間違っていたら、何が起きるか」で考えます。

### 要約で済ませやすいもの

- 参考として目を通しておきたい業界ニュースや社外の記事
- 自分が全体像をつかむための下調べ
- あとで原文を読む前提の「どこを読むべきか」の見当づけ

### 原文を読むべきもの

- 契約書、規約、社内規程など、文言そのものに意味があるもの
- 金額、期限、数量が判断を左右するもの
- 社外に出す文書の根拠になるもの
- 人の評価や処遇に関わるもの

原文を読むべき資料でも、要約が無駄になるわけではありません。「先に要約で全体をつかみ、重要な箇所は原文で読む」という使い方なら、読む順番の地図として役に立ちます。

生成AIの要約は、うまく使えば長い資料に向き合うハードルをぐっと下げてくれます。ただ、**要約は原文の代わりではなく、原文への入口**です。確認する場所を決めておけば、全文を読まなくても、判断に関わる誤りはかなり防ぎやすくなります。まずは次に届いた長い資料で、手順2の「出典の場所をつける」指示だけでも試してみてください。
