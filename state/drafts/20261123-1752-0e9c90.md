# 生成AIで業務マニュアルを作る ベテランの暗黙知を引き出す手順

生成AIにマニュアルを丸ごと書かせるのではなく、「聞き手」と「清書係」として使う。そうすると、ベテランの頭の中にしかないコツを、新人が読んで使えるマニュアルにしやすくなります。

「マニュアルを作っておいて」と頼まれたものの、何から書けばいいか分からない。生成AIに「〇〇業務のマニュアルを作って」と頼んでみたら、それらしい文章は出てきたけれど、うちの職場のやり方とはどこか違う。そんな経験はありませんか。

生成AIは、文章を整えたり、見出しを付けたり、手順を並べ替えたりするのは得意です。一方で、**あなたの職場で実際にどうやっているか**は知りません。何も材料を渡さずに頼むと、どこの会社にも当てはまりそうな一般論のマニュアルになりがちです。

この記事では、ベテランの頭の中にあるコツ(暗黙知)をマニュアルに落とす手順を、5つのステップと、聞き取りメモ・清書結果の見本つきで紹介します。

## なぜ「丸投げ」だと使えないマニュアルになるのか

生成AIに業務名だけを伝えて作らせたマニュアルには、よく次のような問題が出ます。

- **職場のルールが入っていない**:承認者、締め日、使っているシステムの画面名など、固有の情報が抜けます。
- **「迷うところ」が書かれていない**:手順は並んでいても、例外のときにどうするかが書かれていません。
- **もっともらしい誤りが混ざる**:存在しない手順や、実際とは違う順番が、自然な文章で書かれることがあります。

マニュアルで本当に役立つのは、「ここで迷ったらこうする」「この確認を飛ばすと後で困る」といった、経験者だけが知っている部分です。ここは生成AIが自分で知ることはできないので、**人から引き出して、AIに渡す**必要があります。

## 全体の流れ(5ステップ)

1. 対象業務を1つに絞り、ゴールを決める
2. 生成AIに「聞き取りの質問リスト」を作らせる
3. ベテランに聞き取りをして、メモを集める
4. メモを渡して、生成AIにマニュアルの形に整えさせる
5. 新しく担当する人に試してもらい、つまずいた所を直す

順に見ていきます。

## ステップ1:対象業務を1つに絞る

最初に「経理業務のマニュアル」のような大きな単位で始めると、聞き取りも清書も終わりません。まずは**1回の作業で完結する業務**を1つ選びます。

例えば次のような単位です。

- 月末の請求書の発行
- 新しい取引先の登録
- 備品の発注
- 問い合わせメールの一次対応

あわせて、マニュアルのゴールを一文で決めておきます。

> 例:「初めて担当する人が、このマニュアルだけを見て、月末の請求書発行を一人で終えられる」

ゴールが決まると、どこまで書けば足りるかの判断がしやすくなります。

## ステップ2:生成AIに聞き取りの質問リストを作らせる

いきなりベテランに「やり方を教えてください」と聞いても、慣れている人ほど細かいところを省いて話してしまいます。本人にとって当たり前のことは、言葉にしにくいからです。

そこで、生成AIに**聞き取り用の質問リスト**を先に作らせます。

### 依頼文の例

```
あなたは業務マニュアルを作るための聞き取り担当です。
これから、社内で「月末の請求書発行」をしているベテラン社員に話を聞きます。
新しく担当する人がつまずかないマニュアルを作るために、聞くべき質問を作ってください。

条件:
・作業の前(準備)、作業中、作業の後(確認・報告)に分けて
・「いつもと違うケース」「よくあるミス」「判断に迷う場面」を聞く質問を必ず入れる
・専門用語は使わず、1問1つのことだけを聞く
・全部で15問以内
```

### 質問リストで確かめたいこと

できあがった質問リストに、次の観点が入っているかを見ます。足りなければ追加を頼みます。

- **始めるきっかけ**:いつ、何を合図に作業を始めるか
- **使うもの**:システム、ファイル、書類の置き場所
- **判断の基準**:どんなときに上司に確認するか
- **例外**:締め日が休日のとき、金額が違っていたときなど
- **終わりの確認**:何をもって「完了」とするか、誰に報告するか

生成AIの質問リストはあくまで下書きです。自分の職場に合わない質問は削り、聞きたいことを足してください。

## ステップ3:ベテランに聞き取りをする

聞き取りは、可能なら**実際の作業を横で見ながら**行うのがおすすめです。口頭で説明してもらうだけだと、手が勝手に動いている部分が話に出てこないことがあります。

### 段取りの目安

- **時間**:1つの業務につき、まずは30分〜1時間ほどお願いし、足りなければ後日に分けます。一度で全部聞こうとしないほうが、相手の負担も小さくなります。
- **作業日でないとき**:月末の請求書発行のように、月に1回しかない作業もあります。その場合は、前回の書類や画面を開きながら「このときは何をしましたか」と順に再現してもらいます。
- **メモが追いつかないとき**:相手の了承を得て録音し、後で書き起こします。録音を生成AIで文字起こしする場合も、次の「生成AIに渡す前に」の確認をしてください。

### 聞き取りのコツ

- **大事な確認には「なぜ」を聞く**:「この確認をするのはなぜですか」と聞くと、過去のトラブルなど、マニュアルに残すべき理由が出てきます。ただし続けて何度も聞くと問い詰めているように感じさせるので、要所に絞ります。
- **失敗談を聞く**:「新人の頃に困ったことは」「最近あったミスは」と聞くと、注意書きの材料になります。
- **言葉をそのままメモする**:きれいにまとめるのは後で生成AIに任せるので、話し言葉のままで構いません。
- **画面名やボタン名は正確に書き取る**:ここは後でAIが補えない部分です。

### 生成AIに渡す前に

聞き取りメモには、取引先名・個人名・金額など、社外に出せない情報が混ざることがあります。社内のルールで生成AIへの入力が認められている範囲かを確認し、必要なら「A社」「担当者B」のように置き換えてから渡してください。

利用ルールがまだない職場なら、少なくとも次の2つをしてから使いましょう。

- 業務の情報を入れてよいか、上司に一言確認する
- 使うサービスの設定やプランで、入力内容がAIの学習に使われる扱いになっていないかを確かめる

### 聞き取りメモの見本

メモは、きれいでなくて構いません。例えばこのくらいの粒度です。

```
・毎月25日すぎに営業から「今月の納品一覧」がメールで来る。それが合図
・単価が変わった取引先は、先に営業の一覧と見積書を見比べる(去年、旧単価で出して作り直した)
・確認が済んだら、販売管理システムの「請求書作成」画面で、取引先ごとに作る
・締め日が土日なら前の金曜に出す
・作ったPDFは共有フォルダ「請求書/年月」に保存
・発送前に課長に一覧を見せてOKをもらう
```

## ステップ4:メモを渡して、マニュアルの形に整えさせる

ここで初めて、生成AIに清書を頼みます。ポイントは、**メモに書かれていないことを付け足させない**ことです。

### 依頼文の例

```
以下は「月末の請求書発行」についての聞き取りメモです。
これをもとに、初めて担当する人向けの業務マニュアルを作ってください。

ルール:
・メモに書かれていない手順や情報を付け足さない
・メモだけでは分からない部分は、本文に【要確認:〇〇】と書いて残す
・各手順は「何をするか」「どこで(画面・ファイル)」「終わったら何を確認するか」の順で書く
・注意点やよくあるミスは、該当する手順のすぐ下に「注意」として書く
・最後に、聞き取りで出た例外ケースを「こんなときは」の一覧にまとめる

【聞き取りメモ】
(ここにメモを貼る)
```

### 清書結果の見本(1手順分)

上のメモから、例えば次のような形で返ってくれば合格です。

```
手順3:単価が変わった取引先を確認する
・何をするか:今月の納品一覧と、最新の見積書の単価を見比べる
・どこで:営業からのメール(納品一覧)、【要確認:見積書の保存場所】
・終わったら:単価が一致していることを確かめてから、請求書作成に進む
注意:旧単価のまま発行すると、作り直しになります
こんなときは:単価が一致しなかったとき【要確認:誰に確認するか】
```

### 【要確認】を出させる理由

生成AIは、情報が足りないところを、それらしい内容で埋めてしまうことがあります。「分からない所は【要確認】と書く」と最初に指示しておくと、**AIが推測で埋めた部分と、聞き取りで確かめた部分を区別しやすく**なります。

ただし、指示しても印を付けずに内容を足すことはあります。照合を楽にしたいときは、依頼文に「各手順の最後に、根拠にしたメモの行をかっこ書きで添える」と加えると、メモにない内容に気づきやすくなります。

【要確認】が出た所は、もう一度ベテランに聞いて埋めます。

### 出てきた原稿で見る所

- メモにない手順が増えていないか
- 手順の順番が、実際の作業と同じか
- 画面名・ファイル名・締め日などの固有の情報が、メモどおりか
- 「注意」がその手順の近くにあるか

画面の操作が多い業務では、確認が終わった原稿に、画面のスクリーンショットを手順ごとに貼っておくと、読む人が迷いにくくなります。仕上がったマニュアルは、Wordなど職場でふだん使っている形式で、担当者が迷わず開ける共有フォルダに置いておきましょう。

最後の確認は、聞き取りをした本人かベテランにしてもらうのが確実です。

## ステップ5:新しく担当する人に試してもらう

マニュアルが本当に使えるかは、**書いた人ではなく、使う人**にしか分かりません。できあがったら、その業務をまだ担当したことのない人に、マニュアルだけを見て作業してもらいます(練習用のデータや過去の事例で試せると安心です。用意できない場合は、本番の作業でベテランが横で見守る形でも構いません)。

### 試してもらうときのお願い

- 手が止まった所、迷った所に印を付けてもらう
- 書かれている言葉の意味が分からなかった所を挙げてもらう
- 横で見ている人は、なるべく口を出さない

### 直し方

印が付いた所を、もう一度生成AIに渡して直させると早く進みます。

```
以下のマニュアルを、初めての担当者に試してもらいました。
つまずいた箇所と、その理由を書きます。
マニュアルの他の部分は変えずに、つまずいた箇所だけを分かりやすく書き直してください。
新しい情報が必要な場合は、付け足さずに【要確認】と書いてください。

【マニュアル】
(貼る)

【つまずいた箇所と理由】
・手順4:「取引先ごとに作る」の操作が分からなかった
・手順5:どのフォルダに保存するのか書かれていなかった
```

「他の部分は変えずに」と指示するのは、直さなくてよい部分まで書き換えられて、確認がやり直しになるのを防ぐためです。

## 作ったあとに決めておきたいこと

マニュアルは作った瞬間から古くなり始めます。最後に、次の2つだけ決めておきましょう。

- **誰が直すか**:業務の手順が変わったときに、更新する担当者を1人決めておきます。
- **いつ見直すか**:「担当者が替わるとき」「システムが変わったとき」など、見直すきっかけを決めておきます。

更新するときも、変わった点のメモを生成AIに渡し、「該当箇所だけを書き換えて」と頼めば、全体を作り直す必要はありません。

## まとめ

- 生成AIは職場のやり方を知らないので、業務名だけで頼むと一般論のマニュアルになる
- 生成AIには「聞き取りの質問づくり」と「メモの清書」を任せる
- 中身(手順・例外・コツ)は、ベテランへの聞き取りで集める
- 清書では「メモにないことを足さない」「分からない所は【要確認】」と指示する
- 最後は、新しく担当する人に試してもらい、つまずいた所だけを直す

まずは、あなたの職場で「あの人しか分からない」と言われている業務を1つ選び、ステップ2の質問リストづくりから試してみてください。
