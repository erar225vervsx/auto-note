# 生成AIで会議のアジェンダを作る 詰め込みすぎを防ぐ5手順

「アジェンダは生成AIですぐ作れたのに、本番では半分も終わらなかった」。生成AIを仕事で使い始めると、こんな場面に出会うことがあります。

生成AIに会議のアジェンダ(議題と進行表)を頼むと、項目がきれいに並んだ案がすぐに出てきます。見た目は立派なのに、実際に使うと時間が足りない、何を決める会議だったのか曖昧なまま終わる、ということが起こりがちです。

この記事では、生成AIでアジェンダの「たたき台」を作り、人が手を入れて実際に回せる形にするまでの手順を紹介します。特別なツールは不要で、ChatGPT や Claude などの対話型AIであれば同じ考え方で使えます。

## なぜAIのアジェンダは「詰め込みすぎ」になるのか

生成AIは、頼まれたことに対して「抜けのない案」を出そうとする傾向があります。「必要な事項は補って」と頼めば、なおさら項目が増えます。その結果、次のような案になりやすくなります。

- **項目が多すぎる**:60分の会議に8〜10個の議題が並び、1項目あたりの時間が数分しかない
- **時間の合計が合わない**:各項目の分数を足すと、会議の全体時間を超えている
- **「話す」だけで「決める」がない**:「〇〇について議論」と書かれているだけで、終わったときに何が決まっていればよいのかが書かれていない
- **予備の時間がない**:最初から最後までぴったり詰まっていて、少しでも延びると後ろが崩れる

AIは参加者の性格や、その議題がいつも揉めるかどうかを知りません。だからこそ、AIの案は「完成品」ではなく「改善点を探すための出発点」として扱うのが安全です。

## 手順1:AIに渡す前に「会議のゴール」を一文で書く

いちばん大事なのは、AIに頼む前の準備です。次の一文を自分で書いてください。

「この会議が終わったとき、〇〇が決まっている(または、〇〇の状態になっている)」

例を挙げます。

- 「来期の展示会に出るかどうかが決まり、出る場合の担当者が決まっている」
- 「新しい経費精算ルールについて、各部署の懸念が出そろっている」
- 「4月の採用説明会の日程候補が2つに絞られている」

ゴールが「〇〇について話し合う」のままだと、AIも人も「話して終わり」の進行表を作ってしまいます。終わったときの状態を言葉にしておくと、どの議題が必要でどれが不要かを判断しやすくなります。

ゴールが一文で書けないときは、まだ会議を開く準備ができていないサインかもしれません。その場合は、先に関係者とチャットで論点を整理するほうが早いこともあります。

## 手順2:条件をそろえてAIにたたき台を頼む

ゴールが書けたら、AIに条件を渡します。最低限、次の5つを入れます。

- **会議のゴール**(手順1の一文)
- **全体の時間**(例:45分)
- **参加者と役割**(進行役、記録係、決める権限を持つ人)
- **扱いたい議題の候補**(思いつく範囲でよい)
- **出力の形**(番号つきの進行順、各項目の分数、担当者)

あわせて、議題ごとに次の3つのラベルを付けてもらいます。

- **【報告】**:決まったことや状況を伝えるだけの議題
- **【相談】**:意見や情報を出し合い、判断の材料をそろえる議題
- **【決定】**:その場で結論を出す議題

参加者の名前や社外秘の情報をAIに貼るときは、会社のルールに従い、必要に応じて「営業A」「取引先X」のように伏せてから入力しましょう。

そのうえで、詰め込みを防ぐための指示を最初から入れておきます。プロンプトの例です。

```
次の条件で、会議のアジェンダ案を作ってください。

【会議のゴール】展示会に出るかどうかを決め、出る場合の担当者を決める
【全体時間】45分
【参加者】部長(最終決定)、営業2名、総務1名(記録係)、私(進行役)
【議題の候補】前回の展示会の振り返り、今年の出展費用、人手の確保、他の集客方法との比較
【出力の形】番号つきの進行順で、各議題の分数と担当者を書く

【守ってほしいこと】
・議題は多くても4つまで。ゴールに必要ないものは入れず、「外した議題」として最後に理由つきで挙げる
・各議題に【報告】【相談】【決定】のどれかのラベルを付ける
・【決定】の議題には「この議題が終わったときに決まっていること」を一文で書く
・各議題の分数を足した合計を最後に書く。合計は全体時間より5〜10分短くし、残りは予備時間とする
・報告だけで済むものは「事前に資料で共有」として会議から外す案も出す
```

ポイントは「議題の上限」「ラベル」「決まっていること」「合計時間」「外した議題」を指示に入れることです。何も言わないと、AIは項目を足す方向に寄りがちです。

## 手順3:出てきた案をチェック項目で点検する

AIの案が出たら、そのまま共有せず、次のチェック項目を確認します。ここは人が自分の目で見るところです。

### ① 時間を自分で足し算する

AIが書いた「合計」をうのみにせず、各項目の分数を自分で足してください。生成AIは計算を誤ることがあり、合計の表示と実際の足し算が合わない案が出ることもあります。全体時間を超えていたら、その時点で直します。

### ② 予備の時間があるか

会議は予定より延びることが多いものです。全体の時間のうち5〜10分を予備として残しておくと、議論が盛り上がったときも最後の決定まで進めます。45分の会議なら、議題に使うのは35〜40分を目安にすると、慌てずに済みます。

### ③ 【決定】の議題に「決まっていること」が書いてあるか

「人手の確保について議論」ではなく、「出展する場合の当日担当者2名が決まっている」のように、終わったときの状態が書けているかを見ます。書けていない議題は、議論が終わりどころを失いやすくなります。

### ④ 報告だけの議題が混ざっていないか

「前回の展示会の振り返り(報告)」のように、聞くだけで済むものは、事前に資料やチャットで共有すれば会議の時間を使わずに済みます。会議の時間は、その場で顔を合わせないと進まない「相談」と「決定」に回すのが基本です。

### ⑤ 順番に無理がないか

決定に必要な情報が、決定の議題より前に出てくる順番になっているかを確認します。たとえば「費用」と「人手」の情報がそろう前に「出るかどうか」を決める順番になっていたら、入れ替えます。

## 手順4:人にしか分からない事情を足す

ここからは、AIが知らない情報を人が補う段階です。次のような点を考えて、時間配分を調整します。

- **いつも長引く議題はどれか**:過去に揉めた議題や、関係者の意見が分かれそうな議題には、AIの案より多めに時間を取る
- **決める人は最後までいるか**:決定権を持つ人が途中で抜けるなら、決定の議題を前に寄せる
- **事前に読んでおいてほしい資料はあるか**:資料のリンクをアジェンダに書き添える
- **時間切れになったら後回しにしてよい議題はどれか**:あらかじめ決めておくと、当日に慌てずに済む

最後の「時間切れのときの扱い」は、効果が出やすいポイントです。「議題3が終わらなければ、議題4は来週の定例に回す」と書いておくだけで、進行役が判断に迷わなくなります。

## 手順5:共有前に、AIに「ツッコミ役」を頼む

人が手を入れたアジェンダを、もう一度AIに見せて、弱いところを指摘してもらう方法もあります。作るときとは逆の立場で読ませるのがコツです。

```
次の会議アジェンダを、厳しい参加者の立場で読んでください。
・時間が足りなくなりそうな議題
・終わったときに何が決まるのか分かりにくい議題
・事前に共有しておかないと議論が進まない情報
を、それぞれ理由つきで挙げてください。良い点の説明は不要です。

(ここにアジェンダを貼る)
```

AIの指摘がすべて正しいとは限りません。参加者や社内の事情を知っているのは自分なので、納得できた指摘だけを取り入れてください。

## 仕上がりの例

手順どおりに整えると、たとえば次のような形になります。

**会議のゴール**:展示会に出るかどうかを決め、出る場合の当日担当者を決める(45分)

**事前共有**:前回の展示会の振り返りメモと、今年の出展費用の見込み(会議前日までにチャットで共有)

- **1. 出展費用と予算の相談【相談】8分**(総務):事前に共有した費用の見込みをもとに、予算をどこまで使えるかを部長と意見交換する
- **2. 人手の確保【相談】10分**(営業):当日動ける人数と、通常業務への影響を出し合う
- **3. 他の集客方法との比較【相談】7分**(進行役):展示会以外の選択肢を並べる
- **4. 出展するかどうかの決定【決定】10分**(部長):終わったときに「出る・出ない」と、出る場合の担当者2名が決まっている
- **予備時間 10分**

**時間切れのとき**:議題3が7分を超えたら打ち切り、出た論点だけ記録して議題4の決定に進む

議題の合計は35分で、予備を含めて45分に収まります。「前回の振り返り」は報告なので会議の外に出し、費用の数字も事前に共有して、会議では「予算をどこまで使うか」の相談だけを扱います。
