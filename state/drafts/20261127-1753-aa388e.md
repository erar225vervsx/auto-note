# 生成AIでクレーム返信を下書きする 火に油を注がない5手順

お客様や取引先から、怒りのこもったメールが届いた。早く返さなければいけないのに、どう書き出せばいいか分からず、画面を前に手が止まってしまう。そんなとき、生成AIに下書きを頼みたくなるのは自然なことです。

ただ、クレームへの返信は、生成AIに任せると失敗しやすい種類の文章でもあります。たとえば、事情だけを伝えて「お詫びのメールを書いて」と頼むと、まだ誰も決めていない「全額返金いたします」や、確認していない原因の説明が、もっともらしく入ってくることがあります。言い回しが整いすぎて「定型文で済まされた」と受け取られる心配もあります。

この記事では、生成AIを「書き手」ではなく「整理役」と「たたき台づくり」に使い、最後は自分の言葉で送るための5つの手順を紹介します。読み終えたら、次にクレームが来たとき、そのまま手順どおりに進められるはずです。

## 最初に決めておくこと:AIに任せない3つのこと

手順に入る前に、線を引いておきます。クレームの返信では、次の3つはAIに決めさせません。

- **原因**:なぜ起きたのかは、社内で確認した事実だけを書きます。AIは状況を知らないので、推測で原因を作ってしまうことがあります。
- **約束**:返金・交換・値引き・期日など、相手に約束する内容は、決める権限のある人が決めます。
- **送るかどうか**:最終的に送る判断と、送る文面への責任は人が持ちます。

逆に、AIが得意なのは「相手の文面から、事実と要望と感情を分けて整理する」「失礼のない言い回しの候補を出す」「抜けている要素を指摘する」といった作業です。この役割分担を前提に進めます。

## 確認に時間がかかるときは、先に受付の返信を

このあと紹介する手順には、社内での事実確認が含まれます。確認に時間がかかりそうなときは、先に「ご連絡を受け取ったこと」「内容を確認していること」「いつまでに改めて連絡するか」だけを短く返しておきます。この段階では、原因や対応には触れません。ここで時間をとれるので、本番の返信は落ち着いて作れます。

## 手順1:相手の文面を、伏せてから整理させる

まず、届いたメールをAIに読ませて整理させます。ここで大事なのは、貼り付ける前に個人情報や社外秘を伏せることです。

- お客様の氏名・電話番号・住所・メールアドレス
- 注文番号・契約番号・会員番号
- 取引先の社名や担当者名、金額など社外に出せない情報

これらは「Aさん」「注文番号X」のように置き換えてから貼ります。会社で使ってよいAIサービスや入力してよい情報の範囲が決まっている場合は、その社内ルールに従ってください。あわせて、使っているサービスで、入力内容がAIの学習に使われる設定になっていないかも確認しておくと安心です。

伏せた文面を貼ったら、次のように頼みます。

```
以下はお客様から届いたメールです(個人情報は伏せています)。
返信を書く前の整理をしたいので、次の4つに分けて箇条書きにしてください。
1. 相手が書いている事実(いつ・何が・どうなったか)
2. 相手の要望(何をしてほしいか)
3. 相手の気持ち(怒り・不安・困りごとなど)
4. 文面からは分からず、こちらで確認が必要なこと
推測で補わず、書かれていないことは「不明」としてください。

---
(ここに伏せたメール本文)
```

怒っている文章は、読むだけで気持ちが削られます。AIに一度分けてもらうと、「相手は何に困っていて、何を求めているのか」を落ち着いて見られるようになります。特に4番の「確認が必要なこと」は、次の手順の出発点になります。

## 手順2:事実と「できること・できないこと」を自分で書き出す

次に、AIを使わずに、社内で確認した内容を短いメモにします。ここがこの手順の中心です。

- **確認できた事実**:例「配送業者の記録では、到着は予定より2日遅れ」
- **まだ確認中のこと**:例「破損の原因が輸送中か梱包時かは調査中」
- **こちらができること**:例「交換品の発送。発送日は上長の確認後に連絡」
- **こちらができないこと**:例「保証期間外のため無償修理は不可」
- **誰が決めたか**:例「交換対応は課長が了承済み」(これは自分の確認用で、AIには渡さなくて構いません)

このメモは箇条書きで構いません。大切なのは、AIに渡す情報を「確定したこと」だけにしておくことです。確認中のことは「確認中」と明記します。これを曖昧にしたままAIに渡すと、AIが空白を埋めようとして、事実と違う説明や守れない約束が文面に入りやすくなります。

判断に迷ったら、「この一文を相手に書いたら、会社として守れるか」と自問してください。守れるか分からないことは、メモに書かない、または「確認中」とします。

## 手順3:型を決めたプロンプトで、たたき台を作る

手順1の整理と手順2のメモがそろったら、下書きを頼みます。手順1と同じ会話の続きで頼んでも、新しい会話で頼んでも構いません。新しい会話にする場合も、下のプロンプトに必要な情報をすべて貼れば足ります。

その前に、お詫びの範囲を決めておきます。クレームの返信でのお詫びには、大きく2種類あります。

- **不便や不快な思いをさせたことへのお詫び**:落ち度がはっきりしない段階でも使える、範囲を限ったお詫びです。例「ご不便をおかけし、申し訳ございません」
- **こちらの誤りを認めるお詫び**:社内で誤りが確認できたときに使います。例「当社の確認不足により、誤った商品をお送りしてしまい、誠に申し訳ございません」

落ち度が確認できていないのに、AIの下書きが誤りを認める書き方になっていたら、直す必要があります。

毎回ゼロから頼むと出来がぶれるので、型を決めておくと楽です。

```
あなたは、丁寧で誠実なカスタマー対応の担当者です。
以下の情報をもとに、お客様への返信メールの下書きを作ってください。

【条件】
- です・ます調。過度にへりくだらず、言い訳がましくしない
- 冒頭で、連絡へのお礼と、ご不便をおかけしたことへのお詫びを書く
- こちらの誤りを認めるお詫びは、【確定した事実】に当社側の誤り(ミス)が書かれている場合だけにする
- 「確定した事実」と「対応内容」に書かれていることだけを書く
- 原因や対応で、下の情報に書かれていないことは書かず、その箇所には【要確認】とだけ書く
- 返金・値引き・期日などの約束を、自分で付け加えない
- 相手の申し出を「クレーム」と呼ばない
- 全体で400字程度

【相手の要望と気持ち】
(手順1の整理のうち、2と3を貼る)

【確定した事実】
(手順2のメモの「確認できた事実」を貼る)

【対応内容(決定済み)】
(手順2のメモの「こちらができること」を貼る)

【対応できないこと】
(手順2のメモの「こちらができないこと」を貼る。なければ「なし」)

【まだ確認中のこと】
(手順2のメモの「まだ確認中のこと」を貼る。なければ「なし」)
```

ポイントは「書かれていないことは【要確認】とだけ書く」という指示です。こうしておくと、AIが勝手に原因や補償を書き足したときに気づきやすくなります。出てきた下書きに【要確認】が残っていれば、そこは人が埋めるか、文面から外す箇所です。

一度で気に入る文面が出なくても構いません。「もう少し短く」「お詫びの言葉が重なっているので一つにまとめて」のように、直してほしい点を具体的に伝えて調整します。

## 手順4:送る前に5つの点を確かめる

AIの下書きは、そのまま送らず、次の5点を一つずつ確かめます。

- **事実**:手順2のメモにない原因や経緯が書かれていないか。日付・数量・商品名は正しいか。
- **約束**:決めていない返金・交換・期日・再発防止策が書かれていないか。「必ず」「二度と」など、守れるか分からない言い切りがないか。
- **相手の要望への返事**:相手が求めたことに、できる・できない・確認中のどれかで答えているか。要望に触れずにお詫びだけ並べていないか。
- **言葉づかい**:同じお詫びの言葉が何度も重なっていないか。メールに合わない硬すぎる表現や、意味の通らない言い回しが残っていないか。
- **宛先と伏せ字の戻し**:宛先・CC・件名が正しいか。伏せ字にした「Aさん」「注文番号X」が、正しい内容に戻っているか。

最後の項目は見落としがちです。手順1で伏せた情報を、送る文面では正しく戻す必要があります。逆に、別のお客様の情報を下書きに使い回していないかも確認します。

## 手順5:自分の言葉を必ず足す

最後に、AIの下書きの上に、自分の言葉を少しだけ足します。生成AIが書いた文章は整っている反面、どの相手にも当てはまる一般的な言い回しになりがちです。相手によっては、それを「定型文で流された」と感じることがあります。

足すのは、次のような部分です。

- **相手の文面に具体的に触れる一文**:例「楽しみにされていたご注文だったとのこと、本当に申し訳なく思っております」のように、相手が書いた事情に触れる
- **自分が担当していることが分かる一文**:例「本件は私が担当し、確認でき次第ご連絡いたします」
- **次に何が起きるかの一文**:例「調査の結果は、〇日までにメールでお知らせします」(期日は決まっている場合のみ)

全部を書き直す必要はありません。下書きの中で、どの相手にも送れそうな文を一つ選び、目の前の相手にしか書けない文に置き換えるだけでも、印象は変わります。

## 場面別:たたき台の頼み方の違い

同じクレームでも、状況によって返信の組み立ては変わります。手順3のプロンプトの【条件】に、次の一文を足すと、場面に合った下書きになりやすくなります。

- **こちらの誤りが確定している場合**:「誤りを認めるお詫びをし、対応内容と、決まっていれば再発防止の取り組みを書く」
- **原因がまだ分からない場合**:「お詫びは不便をおかけしたことに限り、原因は調査中であることを正直に伝え、いつまでに何を連絡するかを書く。原因の推測は書かない」
- **要望に応えられない場合**:「応えられないことと、その理由を短く伝え、代わりにできることがあれば示す。相手を責める表現は使わない」

原因が分からない段階で返信するのは、不安に感じるかもしれません。それでも、確認中であることと次の連絡の予定を先に伝えておくと、相手は「放置されている」と感じにくくなります。推測で原因を書いてしまい、後で訂正するほうが、信頼を損ねやすいと考えてください。

## やってはいけない使い方

最後に、避けたい使い方をまとめます。

- **届いたメールをそのまま貼り付ける**:個人情報や社外秘が含まれたまま、AIサービスに入力することになります。
- **「いい感じに謝っておいて」とだけ頼む**:事実も対応も渡さずに頼むと、AIが空白を推測で埋めます。
- **下書きを読まずに送る**:AIは決めていない約束を書くことがあります。送る文面はすべて人の言葉として相手に届きます。
- **感情的なまま返信する**:AIの整理を使っても、自分が落ち着いていないときは、いったん時間を置くか、同僚に読んでもらいます。

また、相手が法的な請求をほのめかしている、けがや健康被害が関わっている、といった重い案件は、AIで文面を整える前に、上司や社内の担当部署に相談してください。返信の内容そのものを、個人で判断しないことが大切です。

## まとめ:次のクレームで最初にすること

- 確認に時間がかかるなら、受け取ったことと次の連絡予定だけを先に返す
- 届いたメールの個人情報を伏せ、AIに「事実・要望・気持ち・確認が必要なこと」に分けてもらう
- 確認できた事実と、できること・できないことを自分でメモにする
- 型のプロンプトで、書かれていないことは【要確認】とだけ書かせてたたき台を作る
- 事実・約束・要望への返事・言葉づかい・宛先の5点を確かめる
- 相手にしか書けない一文を、自分の言葉で足して送る

生成AIは、気が重い返信の「最初の一歩」を軽くしてくれます。けれど、相手が受け取るのは、あなたの会社とあなた自身からの言葉です。手順2のメモと、手順5の一文だけは、人の手で書く。この2か所を守るだけで、AIに助けてもらいながらも、誠実さの伝わる返信に近づけます。
